# ADR-003: Baseline Eval Design

- **Status:** Proposed
- **Date:** 2026-10-28
- **Scope:** `src/evals/`, the parse-set manifest under `src/data/eval_sets/`, and the feature canonicalisation shared with `priscianus.verifier`

## Context

Milestone 2 runs the raw model on the parse set (see [plan.md](../plan.md), section 4). Those numbers become the project's problem statement, so the gold data, the sample and the metrics must be fixed before the first run. Changing a definition after a run makes the numbers before and after it incomparable.

**The task.** Each item is one word in one sentence. The model gets the sentence with the target word marked, and returns the word's lemma, UPOS and UD features as JSON. In `raw` mode the model has no tools, and the verifier is not in the loop. The verifier runs after the model, only to give each claim a verdict for scoring.

The treebank facts below come from the UD r2.18 test and train files (checked 2026-10-28).

## Decision 1: Gold source

### Options considered

| Option | Benefits | Downsides |
|---|---|---|
| **A. UD versions of the treebanks.** | One format (CoNLL-U) and one tag set for every treebank. UD feature names are the ones the index already uses (ADR-001), so no second tag mapping is needed. Validated, versioned releases with stable sentence IDs. | The conversions follow different conventions (see Decision 2). The UD Perseus treebank is CC BY-NC-SA, where the original AGLDT release is CC BY-SA 3.0. |
| **B. Native formats** (AGLDT positional tags for Perseus, PROIEL XML). | Closest to the annotators' own decisions. AGLDT Perseus has a more permissive licence. | Two or more tag sets to map to UD, each one more place for mapping bugs. ITTB, LLCT and UDante have no AGLDT version. |
| **C. Both.** | Cross-checks the conversions. | Doubles the mapping work for a check nobody needs yet. |

### Treebanks

| Treebank | Content | Test words | Licence | In the parse set |
|---|---|---|---|---|
| Perseus | Petronius, Ovid, Phaedrus, Vergil | 10,964 | CC BY-NC-SA 2.5 | Yes |
| PROIEL | Vulgate (6,922 words), Cicero (*Att.*, *Off.*), Caesar (*BG*), Palladius | 14,091 | CC BY-NC-SA 4.0 | Yes, except Palladius |
| ITTB | Thomas Aquinas | 29,842 | CC BY-NC-SA 3.0 | Yes |
| LLCT | 8th–9th-century charters from Lucca | 24,079 | CC BY-SA 4.0 | No |
| UDante | Dante's Latin works | 13,474 | CC BY-SA 4.0 | No |
| CIRCSE | Seneca, *Hercules Furens* | 11,503 | CC BY-SA 4.0 | No |

### Decision

**Use the UD versions (option A), pinned to release r2.18, from Perseus, PROIEL and ITTB.**

- **LLCT is left out.** Charter Latin often breaks Classical agreement (*regnante domno nostro Karolus*), so a "correct parse" for a learner is not well defined. 9% of its test words are proper nouns.
- **UDante is left out.** It marks the perfect as `Tense=Pres|Aspect=Perf` (*dixit*), unlike every other treebank, and 495 of its test words are `X` (vernacular quotations). It is a candidate for milestone 5, because its spelling (*eloquentie*, *celis*) is the medieval spelling the Ecclesiastical work needs.
- **CIRCSE is left out** for v1. It is one play, and Perseus already covers Classical verse.
- **PROIEL's Palladius** (1,049 words, Late Latin agricultural prose) is in neither slice, so it is left out.
- The download script fetches the files from the `r2.18` tags and checks pinned SHA-256 checksums. UD tags do not change, so unlike the Wiktextract dump (DATA_LICENCES.md) the checksums can be pinned. Moving to a later UD release means a new manifest version (Decision 4).

## Decision 2: Compared features

### Part-of-speech classes

The model's UPOS is scored by class, not by tag:

| Class | UD tags | Why merged |
|---|---|---|
| verb | `VERB`, `AUX` | UD makes *sum* `AUX` or `VERB` by its syntax. Its morphology is the same. |
| noun | `NOUN` | |
| adj | `ADJ` | |
| pron/det | `PRON`, `DET` | Treebanks split pronouns and determiners differently (*cuius* is `PRON` in Perseus and PROIEL, `DET` in LLCT). |
| uninflected | `ADV`, `ADP`, `CCONJ`, `SCONJ`, `PART`, `INTJ` | Only the class and the lemma are scored. |

### Features

**Compared:** `Case`, `Number`, `Gender`, `Person`, `Mood`, `Tense` (with `Aspect` folded in, see below), `Voice`, `VerbForm`, `Degree`.

**Not compared:** `InflClass`, `InflClass[nominal]`, `PronType`, `Polarity`, `Poss`, `Reflex`, `Person[psor]`, `Number[psor]`, `NumType`, `NumForm`, `NumValue`, `AdvType`, `AdpType`, `PartType`, `NameType`, `Proper`, `Abbr`, `Foreign`, `Form`, `Variant`, `Compound`, `ExtPos`, and `Degree=Dim`. These are lexical or derivational, are present in only some treebanks (`InflClass` is in ITTB and UDante but not Perseus or PROIEL), and are not in the index, so a learner-facing claim would never contain them.

### Canonical form

The treebanks encode the same grammar differently. One canonicalisation function is applied to the gold features, the model's features and the index analyses before any comparison:

| Rule | Evidence |
|---|---|
| Keep `Aspect` only with `Tense=Past` (`Imp` or `Perf`) and with `Tense=Fut|Aspect=Perf` (future perfect). Drop it everywhere else. | Perseus and ITTB write `Aspect=Imp` on every present and future, and `Aspect=Perf` on the pluperfect. PROIEL and the index leave `Aspect` off these. |
| On participles, set `Tense` from `Aspect` (`Imp` → `Pres`, `Perf` → `Past`, `Prosp` → `Fut`), then drop `Aspect`. | Perseus and ITTB mark participles only with `Aspect`. PROIEL and the index use `Tense`. |
| A gerundive is `VerbForm=Gdv` with no `Tense` or `Voice`. `VerbForm=Part` with `Prosp`/`Fut` and `Voice=Pass` becomes `Gdv`. | PROIEL writes `Gdv`. Perseus and ITTB write `Part|Aspect=Prosp|Voice=Pass`. The index writes `Part|Tense=Fut|Voice=Pass` (#29). |
| `Degree=Abs` becomes `Sup`. `Degree=Pos` is dropped. | Perseus and ITTB write `Abs` for superlatives and do not mark the positive. PROIEL writes `Sup` and marks `Pos` on 86% of adjectives. The index does not mark the positive. |
| A multi-valued gold feature (`Gender=Fem,Masc,Neut`, `Case=Acc,Nom`) is a set. Any one member matches. | The annotator left it ambiguous. |

The canonicalisation lives in `priscianus.morphology`, because the verifier needs it as well. Evals import it.

### Gold-anchored comparison

A feature is scored on a token only if the gold marks it on that token. If the model leaves out a feature the gold marks, that is an error. If the model gives a feature the gold does not mark, it is ignored. Without this rule, annotation habits would count as model errors: Perseus marks `Gender` on 46% of pronouns, PROIEL on 99%.

### Relaxations

The three relaxations from the Whitaker's spot-check carry over as follows:

| Relaxation | Model vs gold (exact match) | Claim vs index (verdicts) |
|---|---|---|
| Gender on nouns | **Compared.** The gold marks it on 97–100% of nouns, and it is a fact a learner needs. | **Not compared.** Index noun forms carry no gender, and the lemma's gender is not stored. Revisit when it is. |
| `Degree=Pos` | Dropped by the canonical form. | Dropped by the canonical form. |
| Deponent `Voice` (ADR-002) | **Not compared** on deponent and semi-deponent verbs. | **Not compared** on deponent and semi-deponent verbs. |
| `Person` on pronouns and determiners (#40) | **Compared.** The gold marks it and a learner needs it. | **Not compared.** Index pronoun forms carry no person; it belongs to the lemma (*ego* 1, *tu* 2, *is* 3). |

ADR-002 left open where the deponent flag comes from. **Decision:** from Wiktionary's deponent and semi-deponent headword lines, stored on `lemmas` at build time (#38, done). `matches()` reads `Analysis.deponent`. For a gold lemma that is not in the index there is no analysis to match, so a verb lemma ending in *-or* counts as deponent only where a caller needs the rule without one (a first-person present that ends in *-or* can only be passive in form).

**Convention differences found by the index-vs-gold check (#40, [index-vs-gold.md](../index-vs-gold.md)).** They are not relaxed, so they lower the ceiling, and are recorded here so that they are not mistaken for model errors:

- **Lemmas of participles, gerunds, gerundives, supines, comparatives and superlatives.** The gold gives the verb or the positive; the index gives the participle or the comparative. The lemma links described under Decision 6 close this gap (follow-up issue).
- **Gender and number on personal pronouns.** The gold gives *ego*, *tu*, *nos*, *vos* Gender=Masc and *se* a number; the index has neither.
- **Lemma spelling.** The treebanks, PROIEL and ITTB especially, spell lemmas with medieval or assimilated variants (*adfirmo*/*affirmo*, *inmundus*/*immundus*), and sometimes lemmatise a form differently from Wiktionary. Assimilation variants are matched by a lookup-time fallback (below); other differences (*dolui* → *deoleo*) are not relaxed.

**Assimilation spellings (#58).** The index keeps the spelling Wiktionary uses, and the keys are not folded, so no rebuild or schema change is needed. Instead, a lookup-time fallback matches the prefix assimilations of *ad-*, *in-*, *con-*, *ob-* and *sub-* (*adf-*/*aff-*, *inp-*/*imp-*, *conl-*/*coll-*, and so on; the list is in `morphology/assimilation.py`):

- `lookup_form` tries the variants of the form's prefix only if the exact key has no analysis. Analyses found that way carry `variant = True`. An exact spelling in the index is never replaced by a variant.
- `inflect` tries the variants of the lemma's prefix only if the index has no lemma with the exact key. A lemma that exists without the requested features still raises `NoSuchFormError`.
- Lemma comparison (`lemma_keys`, used by the verifier and by the lemma score) treats a lemma and its prefix variants as the same lemma. `Classification.variant` is true when a claim was matched only through a variant, so that reports can count those apart. The index-agreement report states how many items need the fallback.
- Folding could join two real lemmas. The fallback limits that: it changes only the start of the key, only by the listed pairs, and only on a miss. It cannot hide a wrong reading, since the features are still compared.

The committed baseline reports were scored before this change and still quote their ceilings (79.3% test, 81.3% dev). Re-scoring them with the fallback would raise them by a fraction of a point.

**Ceiling.** The agreement rate is the ceiling quoted next to the baseline numbers: 80.3% of all parse-v1 items and 89.2% of the inflected ones, with the fallback. Seven of those items match only through it. Uninflected words are not in the index by design.

## Decision 3: Sampling

### Candidates

- **From:** the test splits of Perseus, PROIEL and ITTB.
- **Excluded:** `PUNCT`, `NUM`, `PROPN`, `X` and `SYM` tokens; tokens marked `Foreign=Yes` or `Abbr=Yes`; and words inside a multiword token. A word inside a multiword token is one half of a split such as *virumque* → *virum* + *que*, so there is no surface word to show the model. Enclitics belong in the adversarial set.

### Slices

| Slice | Sources | Candidate words |
|---|---|---|
| Classical | Perseus; PROIEL's Cicero and Caesar | 14,280 |
| Ecclesiastical | PROIEL's Vulgate; ITTB | 32,024 |

A sentence's slice comes from its own metadata: the `# newdoc id` author code in Perseus and the `# source` comment in PROIEL. ITTB is all Aquinas.

Both Ecclesiastical sources use Classical spelling (*caelis*, not *celis*). The Ecclesiastical slice therefore tests Ecclesiastical texts and vocabulary, not Ecclesiastical spelling. Spelling variants are tested in the adversarial set and in milestone 5.

### Frequency bands

| Option | Problem |
|---|---|
| Wiktionary | Has no frequency counts. |
| A published core list (e.g. Dickinson College Commentaries) | Covers about 1,000 lemmas, so it cannot separate 1k–10k from rare. |
| Counts over a large raw corpus | The corpus would need lemmatising, either with the index (circular) or with another tool. |
| **Lemma counts from the UD Latin train splits** | Lemmatised by hand, with the same lemma conventions as the gold. No overlap with the test splits that items come from. |

**Decision: count gold lemmas over the train splits of all six UD Latin treebanks in r2.18.** Each treebank's counts are turned into relative frequencies and averaged, so ITTB's 391k train words do not turn the ranking into Aquinas's vocabulary. Lemmas are keyed by the normaliser's `key_loose`. The same exclusions as for candidates apply.

- **top 1k:** rank 1–1,000
- **1k–10k:** rank 1,001–10,000
- **rare:** rank above 10,000, or not in the train splits

Only 11,451 lemmas occur in the train splits, so in practice "rare" means "not seen in about 830k tokens of annotated text". The counts are rebuilt by `build-set` and not committed. Each item's band is frozen in the manifest.

### Quotas

| | Test | Dev |
|---|---|---|
| Per slice | 500 | 150 |
| Total | 1,000 | 300 |

Within each slice and split, by part-of-speech class: verb 35%, noun 25%, adj 15%, pron/det 15%, uninflected 10%. Verbs carry the most morphology, so they get the largest share. Verb, noun and adj are divided by band, 40% top 1k, 35% 1k–10k and 25% rare. Pron/det and uninflected are not divided by band, because they are closed classes: 1,976 of the 1,989 Classical pron/det candidates are in the top 1k. Quotas are rounded by largest remainder.

Candidate words per open-class cell:

| Slice | Class | top 1k | 1k–10k | rare |
|---|---|---|---|---|
| Classical | verb | 2,418 | 1,209 | 174 |
| Classical | noun | 1,785 | 1,397 | 431 |
| Classical | adj | 512 | 491 | 173 |
| Ecclesiastical | verb | 6,481 | 1,018 | 31 |
| Ecclesiastical | noun | 5,271 | 1,422 | 73 |
| Ecclesiastical | adj | 1,342 | 658 | 74 |

Rules:

- **Within the Ecclesiastical slice, each cell is filled half from the Vulgate and half from ITTB.** Otherwise ITTB, with four times the candidates, would supply about 80% of the slice. When one source runs out, the other fills the gap.
- **At most one target word per sentence, across dev and test.** Items are then independent, and no sentence is shown in both splits. The smallest cells are filled first, so that they get first choice of sentences.
- **Shortfall:** a cell with fewer candidates than its quota takes all of them, and the remainder goes to the next more frequent band of the same class. With r2.18 the only short cell is Ecclesiastical rare verbs (31 candidates for about 57 places).
- **Reporting:** the headline is the average over the sample, labelled as such. Every metric is also broken down by slice, class and band. The manifest records each cell's candidate count, so an estimate reweighted to running text can be computed as well.

## Decision 4: Splits

- **Dev and test both come from the treebanks' own test splits.** Perseus has no dev split, and the train splits are used for the frequency counts.
- **Seeded.** Candidates are sorted by (treebank, `sent_id`, word ID) and shuffled with `random.Random(seed)`. The seed is recorded in the manifest. The same r2.18 files and seed always give the same set.
- **Frozen.** The first manifest is `parse-v1`. `build-set` refuses to overwrite a committed manifest. Any change, including a new UD release, makes `parse-v2`, and every run records the manifest version it used.
- **Prompts are tuned on dev only.** Test is run only for reported numbers, and every report says which split it used. The CI smoke set (~50 items) is a fixed, stratified subset of dev.

## Decision 5: Licence

Perseus, PROIEL and ITTB in UD are CC BY-NC-SA, so no treebank text is committed:

- **The parse set is committed as a manifest of IDs.** `src/data/eval_sets/parse-v1.jsonl` has one row per item: `item_id`, `split`, `treebank`, `ud_release`, `file` (e.g. `la_proiel-ud-test.conllu`), `sent_id`, `word_id`, `slice`, `source`, `pos_class`, `freq_band`, and SHA-256 hashes of the form and the sentence text. The hashes detect drift when the files are fetched again. They are not the text. `parse-v1.meta.json` records the seed, quotas, release, file checksums and cell candidate counts.
- **Text is joined back at run time** from the downloaded files in `src/data/raw/`, which is never committed.
- **The eval store holds prompts, and so holds text.** It is gitignored (`*.db`).
- **Committed reports** hold aggregate numbers and item IDs. A failure example cites the target form and its `sent_id`, not the whole sentence.

## Decision 6: Metrics for the raw mode

### Claim and verdict

In raw mode on the parse set, each item gives at most one claim: `{form, lemma, upos, features}`. The verifier compares it with the index:

1. Look up the analyses of the form (`key_loose`), and canonicalise them and the claim (Decision 2). Two analyses that agree on the lemma key and on every compared feature are one **reading**.
2. A reading **matches** the claim if its lemma is the claimed lemma and every feature the claim states has the same value in the reading. A feature the reading lacks is not checked (index gaps such as noun gender). Features the claim leaves out are not held against it here; completeness is scored by exact match.

| Verdict | Meaning |
|---|---|
| **VERIFIED** | The claim matches a reading, and the form has no other reading. |
| **AMBIGUOUS** | The claim matches a reading, and the form has other readings too (*puella*: nominative, ablative or vocative). The claim is not wrong. |
| **CONTRADICTED** | The claimed lemma is in the index, and no reading of the form matches the claim. This includes forms the index has no analysis for, because the index holds the lemma's whole paradigm. |
| **UNKNOWN** | The claimed lemma is not in the index (`has_lemma` is false). The index cannot say whether the claim is true. |

Lemma matching needs the index to link the lemma conventions the gold and the model use with the ones Wiktionary uses: participle lemmas to their verb (*amatus* → *amo*), and comparatives and superlatives to the positive (*melior* → *bonus*). The verifier issue adds these links.

### Metrics

| Metric | Definition |
|---|---|
| **Parse exact match** | The model's part-of-speech class equals the gold's, and every compared feature the gold marks has the gold's value, after canonicalisation. Over all items. |
| **Per-feature accuracy** | For each compared feature: items where the model's value equals the gold's, ÷ items where the gold marks that feature. Broken down by class. |
| **Lemma accuracy** | `key_loose` of the model's lemma equals `key_loose` of the gold lemma, with homograph numbers removed. Over all items. The prompt states the UD lemma conventions (verb for participles, gerundives, gerunds and supines; positive for comparatives and superlatives; the *-or* form for deponents). |
| **Claim accuracy** | (VERIFIED + AMBIGUOUS) ÷ claims |
| **Hallucination rate** | CONTRADICTED ÷ claims |
| **Unverifiable rate** | UNKNOWN ÷ claims |
| **Format failure rate** | Items with no valid JSON claim ÷ items. These items fail exact match, per-feature and lemma accuracy, and give no claim. |

The three claim rates add up to 1. This changes plan.md's definition of claim accuracy, which counted VERIFIED only. A correct parse of an ambiguous form is correct.

### Index disagreements

Exact match is scored against the gold in context; verdicts are scored against the index with no context. Exact match leaves out the lemma, but a verdict depends on the claimed lemma, so the report uses "gold match": exact match and lemma match together. It shows gold match and verdicts together:

| | Gold match | No gold match |
|---|---|---|
| **VERIFIED / AMBIGUOUS** | Correct | A real reading, but the wrong one for this sentence |
| **CONTRADICTED** | **Index disagreement:** the model agrees with the gold, the index does not | Hallucination |
| **UNKNOWN** | Correct, unverifiable | Wrong, unverifiable |

The hallucination rate keeps its definition, because the `verified` mode has no gold to correct it with. The report gives the index-disagreement count next to it, and every such item is checked by hand on dev. Index errors found this way are fixed in the index build, not in the eval.

## Decision 7: Code location

| Option | Benefits | Downsides |
|---|---|---|
| **A. A separate `evals` package in `src/evals/`**, its own uv project with a path dependency on `priscianus`. | Matches the repo layout (CLAUDE.md) and plan.md's `python -m evals run`. Eval-only dependencies (`conllu`) and eval code stay out of the product wheel and the Docker image. Evals can only use `priscianus`'s public interface, as any caller does. | A second `pyproject.toml` and lockfile. `make lint` and `make test` must cover both. |
| **B. A `priscianus.evals` subpackage.** | One project, one lockfile. | Eval code and its dependencies ship with the product. The eval can reach into private modules, which makes it easier to grade the system with its own internals. |

**Decision: option A.**

```
src/evals/
  pyproject.toml          # depends on priscianus = { path = "../backend", editable = true }
  evals/
    __main__.py           # CLI
    parse_set.py          # build-set: candidates, bands, quotas, manifest
    gold.py               # read CoNLL-U, join the manifest to the text
    score.py              # exact match, per-feature, lemma, verdict rates
    store.py              # SQLite eval store
  tests/
```

The CLI runs from `src/evals`:

```
uv run python -m evals build-set --set parse --version v1
uv run python -m evals run --set parse --split dev --mode raw --model claude-haiku-5-5
uv run python -m evals score --run <id>     # re-verify and re-score without API calls
uv run python -m evals report <id> [<id> ...]
```

`make eval ARGS="..."` wraps it, `make eval-smoke` runs the smoke set, and `make eval-data` downloads the UD files. The scoring code is checked by mypy in strict mode, as `morphology/` and `verifier/` are.

## Decision 8: Eval store

SQLite at `src/evals/results/evals.db`, gitignored. Starting sketch (column names may change during implementation):

```
runs(id, created_at, git_sha, set_name, manifest_version, split, mode, model,
     prompt_version, prompt_hash, index_build_hash, ud_release, params_json, status)
items(id, set_name, manifest_version, split, treebank, sent_id, word_id,
      slice, pos_class, freq_band, gold_json)        -- gold_json: canonical gold, lemma, class
responses(id, run_id, item_id, cache_key, raw_text, parsed_json, format_error)
claims(id, response_id, ordinal, form, lemma, upos, features_json)
verdicts(id, claim_id, index_build_hash, verdict, readings_json)
scores(id, response_id, exact_match, lemma_match, features_json)  -- per-feature results
costs(id, response_id, model, input_tokens, output_tokens, cache_read_tokens,
      cache_write_tokens, usd, latency_ms, cache_hit)
response_cache(cache_key, model, request_json, response_json, created_at)
```

- **Costs are per API call**, not per response, because `tools` and `verified` mode make several calls per item. Run totals and p50/p95 latency are views.
- **Verdicts are keyed by `index_build_hash`.** After an index rebuild, `score` re-verifies the stored claims without new API calls.
- **Cache key:** SHA-256 of the canonical JSON (sorted keys, no whitespace) of the full Messages API request body (model ID, system prompt, messages, tools, output schema, `max_tokens`, thinking and sampling settings), plus a `sample` number that defaults to 0. The same request returns the cached response, so re-running a report costs nothing. A higher `sample` number asks for a fresh response to the same request, to measure run-to-run variance. Run IDs, timestamps and the API key are not part of the key. A cache hit records `cache_hit = 1` and $0 in `costs`; the original cost stays on the cache row.

## Consequences

- **Follow-up issues before the first scored run:** the UD download script with pinned checksums; the participle and degree lemma links; the shared canonicalisation function.
- The headline numbers describe a stratified sample that overweights rare lemmas and verbs compared with running text. Reports say so, and give the reweighted estimate beside them.
- The Ecclesiastical slice does not test Ecclesiastical spelling.
- The Vulgate, Caesar, Cicero and Vergil are almost certainly in the model's training data, and the UD treebanks may be too. A model may remember a parse instead of working it out. Rare-band results are the least affected, and the adversarial set has no published source to remember.
- Index gaps can still count as hallucinations. The index-disagreement count makes them visible, and fixing them improves every mode at once.
- The UD-derived frequency ranks could also fill `lemmas.freq_band` for the drill filters (ADR-001). That is decided in the issue that builds `list_lemmas`.
- Adding UDante, LLCT or CIRCSE later, or moving to a new UD release, means a new manifest version, and results across versions are not compared directly.
